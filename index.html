Teach a computer to watch video, on NVIDIA GPUs

Suppose you have many cameras and you want a computer to watch them for you. For example, to spot a worker without a helmet, count people at a gate, or see someone in a restricted area. This course shows how, using NVIDIA’s tools for vision AI. You learn each piece in plain words, build it, and prove that it works with an assignment.

The tools, one by one

The top row of the picture is the system that runs all day and reads live video. The bottom row is how you make the models it uses. Green outlines are NVIDIA tools.

NVIDIA GPU, driver and CUDAMade by NVIDIA

A GPU is a chip with thousands of small cores. AI models and video decoding run much faster on it than on a normal CPU. The driver lets the computer talk to the GPU. CUDA is the software layer that AI tools use to run on it.

What it does for you: it makes everything else fast enough to run in real time.

Docker and the NVIDIA Container ToolkitDocker is open source; the toolkit is from NVIDIA

Docker packs a program together with everything it needs, so it runs the same on every machine. The toolkit lets those containers use the GPU.

What it does for you: you start NVIDIA’s ready-made tools with one command instead of installing dozens of libraries by hand.

DeepStreamMade by NVIDIA

A toolkit for building video-analytics pipelines. It reads many camera streams at once, decodes them on the GPU, runs AI models on batches of frames, follows objects from frame to frame, and gives you the results. It is built on GStreamer, a common media framework.

What it does for you: it replaces the hardest part, handling lots of live video quickly, so you only write the rules.

PeopleNet and NGCMade by NVIDIA

NGC is NVIDIA’s online catalogue of containers and ready-made models. PeopleNet is one of them: a model that finds people in video.

What it does for you: you can detect people on day one, without training anything.

TAO ToolkitMade by NVIDIA

TAO stands for Train, Adapt and Optimize. You start from a pre-trained model and fine-tune it on your own labelled pictures. You write a short settings file instead of training code, and TAO exports the result as an ONNX file.

What it does for you: you can teach a model something new, like “helmet on or off”, with much less data and code.

TensorRT and ONNXTensorRT is from NVIDIA; ONNX is an open format

ONNX is a common file format for models, so they can move between tools. TensorRT reads an ONNX model and builds an “engine” file, tuned for your exact GPU, that runs faster.

What it does for you: the same model runs several times faster, so one GPU can watch more cameras.

Grounding DINOOpen source

A model that finds things in a picture from a text description, such as “a helmet”. You do not train it first.

What it does for you: it draws the first boxes on your pictures, so people only check and fix them. This saves labelling time.

SAM 2Open source, from Meta

Segment Anything Model 2. Once you mark an object in one frame, it can follow that object through a video.

What it does for you: label a worker once and carry the answer across all the frames where that worker appears.

ControlNet and Stable DiffusionOpen source

Image-generation tools. With “inpainting” you can change one part of a real photo, for example remove a helmet from a worker’s head.

What it does for you: it can create rare examples, like workers without helmets, when real footage has very few. Use them for training only.

OpenCVOpen source

A library for working with images and video: reading frames, drawing zones, brightening dark pictures.

What it does for you: small image jobs, such as improving night pictures or checking if a person stands inside a zone.

What you can build with it

Safety and security

  • Check that workers wear helmets and vests
  • Alert when someone enters a restricted area
  • Spot people close to moving machines

Counting and flow

  • Count people or vehicles at a gate
  • Measure queues and waiting time
  • Find busy hours on a site or in a shop
What this stack does not do for you. It finds and follows objects, and it can run your models quickly. It does not know your rules, and it does not promise accuracy. You decide when an alert is raised, and you must test every model on your own cameras. Topics 6 and 9 show how.

Model libraries Where to find a model before you train one

You rarely start from nothing. A good model library can save you weeks. These are the main places, and they are used for different things.

TAO model zooNVIDIA, on NGC

It has two kinds of models. Purpose-built models do one job well: PeopleNet finds people (it has three classes: people, bags and faces), TrafficCamNet and DashCamNet find vehicles, FaceDetect-IR finds faces in dark infrared pictures. General-purpose vision models are starting points that you fine-tune on your own data, in more than a hundred combinations of network and backbone. Newer foundation models, such as NV-DINOv2 and a Grounding DINO, are listed too.

Best when you want to fine-tune with TAO and run in DeepStream.

How to choose a model

  • Task fit. Does it do your exact job, with your classes?
  • Your own pictures. Test it on 50 of your own images before you trust any claim.
  • Speed on your GPU. A model that is too slow for your camera count is the wrong model.
  • Input size. Small, far objects need a higher input resolution.
  • Format. Can it become ONNX and then a TensorRT engine?
  • Licence. Is commercial use allowed? Some weights are research-only.
  • Support. Is it still maintained, and who answers questions?

Making models smaller and faster Quantisation, pruning and distillation

A model that is accurate but too big or too slow is not useful on a camera box. There are three main ways to shrink a model. You can use them one after another.

TechniqueWhat it doesMain benefitMain riskEffort
QuantisationStores numbers with fewer bits, for example FP16 or INT8 instead of FP32.Faster and smaller, often with little change in accuracy.INT8 needs calibration data, or training that expects it. Accuracy can drop on rare cases.Low to medium
PruningRemoves parts of the network that matter little, such as channels or weights.A smaller network that runs faster.Accuracy falls, so you usually fine-tune again afterwards.Medium
DistillationA big accurate “teacher” model teaches a small “student” model.A small, fast model closer to the teacher’s accuracy than it would reach alone.Needs the teacher’s predictions on plenty of data, and extra training time.Medium to high

Distillation in plain words

Think of a master and an apprentice. A normal label only says “this is a helmet”. A teacher model says more: “90% helmet, 8% cap, 2% hood”. That extra information shows how the classes relate, and a small student can learn from it. This is called knowledge distillation.

An example with this course. Use a large detector, too heavy for the camera box, as the teacher. Run it on your footage to produce predictions. Train a small detector, light enough to run on the box, to copy those predictions. This is close in spirit to what you did in topic 10, where Grounding DINO gave first-guess boxes. Always check the student on your own real test set.

NVIDIA Model Optimizer is NVIDIA’s library for this work. It brings together quantisation, pruning, neural architecture search, distillation and sparsity, and it is free to install. It was called TensorRT Model Optimizer until it was renamed in December 2025. Several of its recipes are aimed at large language models, but the ideas are the same for vision. TAO also has pruning and quantisation steps for several networks, so check the documentation for yours.

Model Optimizer on GitHub Model Optimizer documentation TensorRT documentation

A sensible order. First pick the right-sized model. Then use FP16 through TensorRT. Use INT8 only if you still need more speed. Prune or distil when you need a smaller model. After every step, measure again on the real test set.

Serving models When you need an API, not a video pipeline

DeepStreamThe video route

Video goes in, and metadata comes out. It is the right tool when cameras are the main input. DeepStream can also use Triton as its inference back end.

Connects to the course: topics 2 to 6.

Dynamo-TritonFormerly Triton Inference Server

An open-source server that runs models from many frameworks behind one API. Its dynamic batching groups many small requests into larger batches to keep the GPU busy. NVIDIA renamed it in March 2025, when it became part of the NVIDIA Dynamo platform. Dynamo itself is a separate framework for serving large generative models across many GPUs.

Use it when other programs send pictures or text and wait for an answer.

Triton on GitHub

NIM microservicesReady-made model containers

A model, its optimised engine and an API, packed in one container. You start it and call it.

Use it when you want a working model service quickly, without building the serving parts yourself.

Edge, cloud and hardware

Data-centre and workstation GPUsWhere most of this course runs

Powerful and flexible. Good for training, and for servers that read many cameras. Check each model’s number of video decoders, because decoding can be the first limit (topic 3).

JetsonSmall, low-power edge modules

Compact computers with an NVIDIA GPU, made for cameras, robots and machines. DeepStream and TensorRT run on them, so you can build once and run on a server or at the edge. Models usually need to be smaller, which is where quantisation and distillation help.

Jetson and embedded computing

Cloud GPUsRent, do not buy

Good for a first trial, for training bursts, and for the supported-GPU test when you do not own one. Costs add up if you leave them running.

Simulation and synthetic data

Omniverse and ReplicatorNVIDIA

Build a 3D scene and render thousands of pictures from it, with perfect labels for free. It helps for rare or dangerous cases that you cannot film. The risk is the gap between simulated and real pictures, so always test on real footage.

Connects to the course: topic 12, where you edited real photos instead of rendering new ones.

NVIDIA Omniverse

Isaac SimNVIDIA, for robots

A simulator for robots and machines, built on Omniverse. Use it to test and train robot software before a real robot exists.

Language and multimodal AI

NeMoNVIDIA

A framework to train and customise large language, speech and multimodal models. The workflow is the same as in this course: start from a pre-trained model, fine-tune it on your data, optimise it, then serve it.

NeMo framework

TensorRT-LLMNVIDIA, open source

TensorRT’s counterpart for large language models. It makes text models run faster on NVIDIA GPUs.

TensorRT-LLM on GitHub

Vision-language modelsOpen and NVIDIA

Models that read pictures and answer in words, or find objects from a description. Grounding DINO, which you met in topic 10, is one kind. They are slower than a small detector, so people often use them offline to label data, and run a small model live.

Data science on the GPU

RAPIDSNVIDIA, open source

GPU versions of familiar data tools: cuDF works like pandas, and cuML works like scikit-learn. Use them to prepare and analyse large tables, such as years of alert logs.

Reference

Words you will meet

Short answers in plain words. Terms from the ecosystem page are at the end.

Stream
Live video from one camera, usually sent over the network.
RTSP
The usual way IP cameras send video over a network.
Decode
Turn compressed video into pictures (frames) a model can read.
Inference
Running a trained model on new data to get a result.
Batch
A group of frames processed together, which uses the GPU efficiently.
Tracker
Software that links the same object across frames and gives it an ID.
Metadata
The results DeepStream attaches to each frame: boxes, classes, scores and IDs.
Fine-tuning
Teaching an existing model a new job with your own examples.
Precision and recall
Precision: of the alerts raised, how many were right. Recall: of the real problems, how many were found.
Engine
A model file that TensorRT has optimised for one specific GPU.
Teacher and student
In distillation, the big accurate model (teacher) and the small fast model that learns from it (student).
Distillation
Training a small model to copy the behaviour of a larger one.
Quantisation
Storing a model’s numbers with fewer bits, such as FP16 or INT8, to run faster.
Pruning
Removing parts of a network that matter little, to make it smaller.
Calibration
Running sample data through a model so INT8 can pick good number ranges.
Pseudo-labelling
Using a model’s predictions as labels to train another model.
Foundation model
A large model trained on very broad data, used as a starting point for many jobs.
Open-vocabulary
A model that finds things you describe in words, not only a fixed list of classes.
NIM
NVIDIA’s ready-made model containers, with an API.
Dynamo-Triton
The server formerly known as Triton Inference Server, used to serve models behind an API.
Jetson
NVIDIA’s small, low-power computers for the edge.
Sim-to-real gap
The difference between simulated pictures and real ones, which can make a model fail on real footage.
Drift
Accuracy that slowly falls because the real world, or the cameras, changed after training.
mAP
Mean average precision, a common single score for object detectors.
